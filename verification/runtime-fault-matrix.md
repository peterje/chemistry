# Durable runtime fault matrix

Every runtime transaction now has a stable operation name. The deterministic store adapter can fail the next matching operation immediately before commit or immediately after commit while reporting failure to the caller. The turn adapter can pause before its first event and records request snapshots, executions, and partial persistence.

| Named transition / boundary  | Before-commit evidence                                                                    | After-commit evidence                                             | Convergence invariant                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `admit`                      | No runtime record                                                                         | One operation/stream persisted although caller saw failure        | Same submission ID returns exactly that operation; queue length remains one                        |
| `claim`                      | Operation remains FIFO head                                                               | Claimed generation is durable                                     | Retry uses a new fenced generation and executes one logical turn                                   |
| `persist-request-snapshot`   | Claimed operation retains prior safe snapshot                                             | New context/history/model snapshot and ledger entry are durable   | Retry captures/persists a current snapshot before inference                                        |
| `mark-streaming`             | Operation stays at preparing                                                              | Streaming checkpoint and pending inference effect are durable     | Retry fences the abandoned generation and terminalizes coherently                                  |
| `append`                     | Event is neither stored nor published                                                     | Sequence 0 is durable although producer saw failure               | Reconnect replay recovers committed/unacknowledged data; no phantom event                          |
| `settle`                     | Normal failure/retry paths retain nonterminal ownership                                   | Completed terminal is durable although producer saw failure       | Re-running returns one retained stream/terminal and no duplicate operation                         |
| `schedule-recovery`          | Failed producer remains generation-fenced and lease-bounded                               | One incident/alarm is durable                                     | Retry or due alarm converges on the same operation without unbounded execution                     |
| `wake`                       | Old ownership remains until retry                                                         | One incident identity is committed despite reported failure       | Retry preserves incident, operation, and attempt zero                                              |
| `prepare-recovery` claim     | Scheduled incident remains unclaimed                                                      | New attempting generation/lease is durable but runner is lost     | Expired lease is reclassified; a later current alarm completes recovery                            |
| `prepare-recovery` stale     | Stale alarm intent remains for retry                                                      | Stale intent is consumed although caller saw failure              | Retry leaves no stale intent; wake durably rearms a current fenced/debounced alarm                 |
| `begin-phase-effect`         | No partial effect runs                                                                    | Pending stable key is durable before external persistence         | Pending key may rerun at least once under deterministic assistant identity                         |
| external partial persistence | Deterministic assistant ID is written before ledger completion                            | Transcript may be ahead of runtime ledger                         | Reconciliation or idempotent retry produces one assistant message                                  |
| `complete-phase-effect`      | Transcript exists while ledger is pending                                                 | Stable key is completed although caller saw failure               | Completed key is skipped; transcript-terminal reconciliation avoids re-inference                   |
| `reconcile-terminal`         | Incident remains recoverable                                                              | Completed runtime terminal is durable although caller saw failure | Retry observes the one terminal and performs no model execution                                    |
| `cleanup`                    | Expired stream remains                                                                    | Expired stream/operation are already gone                         | Retry reports zero after an ambiguous committed deletion                                           |
| Replay-to-live handoff       | Live event is parked before ACK/backlog drain                                             | Overlap is visible in durable backlog and pending buffer          | One increasing sequence; overlap dedupes; overflow forces reconnect                                |
| Stale cursor / owner / alarm | Beyond-high-water cursor, stale generation, early timestamp, or expired lease is injected | N/A—guards run at transition commit                               | Cursor cannot advance the gate; stale owner cannot mutate; early alarm waits; stale alarm consumes |
| Recovery exhaustion          | Attempt/work/no-progress/OOM limits are crossed                                           | Repeated exhaustion call sees existing terminal                   | One durable failed terminal and no additional model execution                                      |
| Lost queued runner           | Ephemeral runners disappear after admission                                               | Admission already durable                                         | Wake exposes FIFO head; alarm restoration executes queued prompts in order                         |
